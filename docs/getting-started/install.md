# Install Relay

This page walks a fresh machine from zero to a working `rly` CLI on
macOS, Linux, and Windows. Every shell block tagged `run` is executed
end-to-end by the docs codebase-alignment audit
(`scripts/docs/audit-codebase-alignment.py`); if a step on this page
ever drifts from what the OSS repo actually does, the audit fails and
the page does not ship.

Relay is the OSS half of a two-repo product (see §Project structure
in `planning/epochly-replay-spec.md`). This page covers the public
`epochly-inc/relay` repo only -- the private hosted plane has its own
install path that is not in scope here.

## Prerequisites

| Tool | Minimum version | Why |
|---|---|---|
| `git` | 2.30+ | Cloning the public repo. |
| Python | 3.12+ | The SDK + CLI + sidecar are Python 3.12+ workspaces (`pyproject.toml` `requires-python = ">=3.12"`). CI tests 3.12 / 3.13 / 3.14. |
| Node.js | 22+ | The TypeScript SDK + Cloudflare Worker code (`package.json` `engines.node = ">=22"`). CI tests 22 / 24 / 26. |
| `uv` (recommended) | 0.4+ | The repo uses a `uv` workspace; `uv sync --all-packages` installs every member. Install from <https://docs.astral.sh/uv/>. |

`uv` is strongly recommended. Without it you can still install
individual packages with `pip`, but the workspace bootstrap path on
this page assumes `uv`.

## Step 1 -- Verify your toolchain

Run these from any directory; nothing in the repo is needed yet.

```bash run
uv --version
git --version
python3 --version
node --version
```

Each command should print a version line. If any one fails, install
the missing tool before continuing -- the install will not recover
later if a prerequisite is missing now.

## Step 2 -- Clone the public repo

```bash run
git clone --depth 1 https://github.com/epochly-inc/relay.git
```

The repository is Apache 2.0 licensed (`LICENSE` at the root) and
contains the SDKs, CLI, schemas, contract engine, evidence verifier,
and the local-sidecar app. Nothing on this page requires a Relay
account, hosted credentials, or network access beyond `pypi.org`,
`registry.npmjs.org`, and the clone above.

## Step 3 -- Install workspace dependencies

### macOS and Linux

From inside the freshly-cloned `relay/` directory:

```bash
cd relay
uv sync --all-packages
```

`uv sync --all-packages` is the canonical bootstrap command -- it
matches `.ops/manifest.yaml` `bootstrap-python` exactly. Every member
listed in the top-level `pyproject.toml` `[tool.uv.workspace]` block
(SDK, CLI, schemas, contracts, gate, evals, verifier, ACEF, replay
proxy, local-sidecar, replay proxy) is installed in editable mode
into a single `.venv/`.

### Windows (PowerShell)

The same workflow works on Windows 11 + PowerShell 7. The only
difference is the venv activation path -- `uv sync` creates
`.venv\Scripts\Activate.ps1` instead of `.venv/bin/activate`.

```powershell
cd relay
uv sync --all-packages
.venv\Scripts\Activate.ps1
```

If you prefer to activate the venv manually on macOS or Linux:

```bash
source .venv/bin/activate
```

Activation is optional when you invoke commands through `uv run`
(shown below); `uv run` discovers and uses `.venv/` automatically.

## Step 4 -- Verify the CLI

The `rly` binary lands in `.venv/bin/rly` (or `.venv\Scripts\rly.exe`
on Windows) after `uv sync --all-packages`.

```bash
uv run rly --version
```

Expected output (a single JSON line on stdout):

```json
{"schema_version":"relay.cli.version.v1","version":"0.0.0","python":"3.14.3","platform":"darwin"}
```

Field meanings:

- `schema_version` -- `relay.cli.version.v1`; never changes within
  the v1 schema generation.
- `version` -- the published `rly` version (matches the `epochly-relay`
  PyPI release you installed).
- `python` -- the interpreter version `rly` is running under.
- `platform` -- one of `darwin` / `linux` / `win32`.

If you see a JSON envelope on stdout and `rly` exits 0, the install
is complete.

## Step 5 -- Explore the CLI

`rly --json help` walks every subcommand with its options, help text,
and exit-code table:

```bash
uv run rly --json help
```

The same envelope is rendered as one Markdown page per subcommand
under [`reference/cli/`](../reference/cli/index.md). The page set is
auto-generated by `scripts/docs/build-cli-reference.py`; if you ever
need to know what a flag means, the reference is the source of
truth.

## Common issues

### `uv: command not found`

The `uv` CLI is not installed or not on your `PATH`. Install it from
<https://docs.astral.sh/uv/> -- the project page lists one-line
installers for macOS, Linux, and Windows. After install, open a new
shell so the `PATH` update takes effect, then re-run `uv --version`.

### Python is older than 3.12

The workspace `requires-python = ">=3.12"`; `uv sync` will refuse to
proceed against 3.11 or older. Install a 3.12+ interpreter (the
fastest path on any platform is `uv python install 3.12`) and re-run
`uv sync --all-packages`.

### Node is older than 22

The `package.json` declares `engines.node = ">=22"`. Node 20 reached
end of life on 2026-04-30; please upgrade. On macOS/Linux:
`nvm install 22 && nvm use 22`. On Windows: install Node 22 from
<https://nodejs.org/>.

### `uv sync` reports a network error

`uv sync` fetches from `pypi.org` and `files.pythonhosted.org`. If
your environment blocks egress to those hosts, configure your proxy
via `HTTPS_PROXY` before retrying, or use a private package index
via `UV_INDEX_URL`.

### `rly: command not found` after `uv sync`

Either the venv is not active or you are not invoking via `uv run`.
The reliable form on a fresh shell is always `uv run rly ...`.
Manual activation (`source .venv/bin/activate` on macOS/Linux or
`.venv\Scripts\Activate.ps1` on Windows) lets you drop the `uv run`
prefix.

### `rly --version` prints traceback / exits non-zero

Exit code 70 means an uncaught internal error -- file an issue with
the full traceback and your `uv run rly --version` output. Exit code
64 means a CLI usage error (wrong flag). See the
[error reference](../reference/errors/index.md) for the full code table.
